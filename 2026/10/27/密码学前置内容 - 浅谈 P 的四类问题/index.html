密码学前置内容 - 浅谈 P 的四类问题

密码学前置内容 - 浅谈 P 的四类问题

2026-10-27

密码学, 复杂性理论, 数学

P 与 NP 的问题，作为千禧年难题之一，相信大家都略有耳闻。这实际上算是一点计算复杂性理论的内容，与密码学的关联说大也不见得，如果不是做理论密码设计，实际上大概了解即可（至少不用像专精这一方面的数学家或者理论计算机学者），说小的话，还是要有一定的理解的。所以，本章会浅谈四类问题，简单介绍概念并且举一些和密码学相关的例子，不会太深入。如果有机会，我可能会开一个计算复杂性理论的专题进行讲解这门课程。

预备知识

先来讲讲多项式，如果在环论里面，可能会有不同的说法，所以大家如果想要严谨定义，请去看环论部分内容。这里我们以中学初等数学版本，多项式就是一元 n 次方程，形如 anxn+an−1xn−1+⋯+a2x2+a1x1+a0 的表达式。

时间复杂度：表明问题扩大后，程序需要的时间长度增长地有多快。

  • 多项式级复杂度： O(1),O(na) 等等，这些我们认为是可以接受的，n 增长到需要大小大概率是可以完成程序运算的。
  • 超多项式级复杂度： O(an),O(n!) 等等，这些我们认为是增长爆炸的，n 增长到需要大小大概率是无法完成程序的。

归约（也叫约化），这是个在密码设计里很常见的概念。对于一个难度不小于问题 A 的问题 B，如果 A 可以多项式时间归约到 B，那就是说如果我有一个可以解决 B 的方法，我就可以只用多项式时间的转化，可以借此解决 A，这个转化的过程就叫做归约。简而言之，一个问题 A 可以归约为 B 的含义就是，可以用问题 B 的解法来解决问题 A。也可以认为问题归约后的问题可能会变难。

举个例子，求解一个一元一次方程 A 和求解一个一元二次方程 B，如果会求解 B，那么一定会求解 A。那么我们可以说，A 可以归约到 B。

哈密顿（Hamilton）回路问题，从图中的一个顶点出发，沿着边行走，经过图的每一个顶点，且每个顶点仅访问一次，之后再回到起始点的一条路径。

P 类问题

P 指的就是多项式（polynomial），定义：一个可以在多项式时间复杂度内可以解决的问题。这个的例子有很多，例如欧几里得算法求最大公约数、快速幂和数的排序问题。为什么我们要研究这个，以多项式为标准而不是其他的呢？

因为我们计算机成立的数据是非常大的，想象一下，当计算机处理的数据达到 100 万个的时候，时间复杂度为 O(n2) 和 O(2n) 的算法，所需的运行次数是天壤之别，指数级的可能要运行好几天，但是多项式级的时间是可以接受的。所以一般我们也只在乎一个问题是否存在多项式算法，而一个时间复杂度比多项式还要复杂的算法研究起来几乎是没有意义的。

NP 类问题

NP 指的是非确定是多项式（Nondeterministic polynomial），定义：可以在多项式的时间里验证一个解的问题。即给出一个答案，可以很快（在多项式时间内）验证这个答案是对的还是错的，但是不一定能在多项式时间内求出正确的解。

注意 NP 问题不是非 P 类问题，P 类问题是 NP 问题的子集，因为 P 类问题算是可以在多项式时间内验证，也可以在多项式时间内求解的问题，它也是满足 NP 问题的定义的。

前面我们说的哈密顿回路问题就是一个 NP 问题。再举个不太恰当但是比较好理解例子，数独问题。对于一个九乘九的数独，一天应该可以完成了吧，如果是大手子可以很快。但是如果我是给你一个答案，对照着数独的规则，可以在几分钟内就验证这个答案是否是正确的，至少比解出正确答案也快得多。

如果增加一些规则变成 26 乘 26 的数独（我不知道有没有，瞎编的，意思是这个意思），则几乎不能在多项式时间内找到正解。如果枚举的话，有将近 1026∗26 种情况。但是如果我给的是一个答案，仍然是可以根据规则，在多项式时间内判断这个答案是否是正确的。

密码学里面很多问题就是这样的 NP 问题。例如大数分解问题，如果给一个很大的数（达到 1024 位的数甚至更大），分解出它的因子是很困难的，但是如果我们是给定分解好的因子，去验证是不是真的是它的因子，那很简单，乘起来看一下是不是一样就可以了。同样的，离散对数问题等等都是这样的问题。

NPH 问题

NPH（NP-hard）问题，我们就叫 NP 难问题吧。定义就是一类问题，所有 NP 问题都可以以多项式时间归约到它。简单来说，为了解决 NP 问题 A，先将问题 A 归约到另一个问题 B，解决 B 问题同时也间接解决了问题 A。问题 B 就是一个 NP 难问题。

注意 NP 难问题并不完全包含 NP 类问题。因为一个问题规约后会变得更难，就不一定还能在多项式时间内验证答案。既然 NP 难问题和 NP 类问题是交叉的，那么交叉的这一块是什么，就是我们后面讲到的 NPC 问题。

举个 NP 难问题的例子吧。旅行商求最短回路问题：设一个人需要从香港出发，经过广州，北京，上海等等 n 个城市，最后回到香港。任意两个城市之间都有飞机直达，单双向的票价不等。求总路费最少的行程安排。

想要知道所有方案中花费最少的，必须检查所有可能的旅行安排才能找到，即 (n−1)! 种方案，很显然这不是 P 问题。给出任意一个行程安排，你能算出总路费，但是无法在多项式时间内验证这条路是否是最短路。所以不是 NP 问题。

我们回看前面讲的哈密顿回路问题，是不是可以看作一个不算钱的旅行商问题，也就是说可以归约到旅行商问题。如果我们可以解决旅行商问题，那么说明我们可以解决哈密顿回路这个 NP 问题，因此这个问题是 NP 难问题。

NPC 问题

NPC（NP-complete）问题，我们叫 NP 完全问题。前面我们就说了它的定义了，就是所有既是 NP 问题，又是 NP 难问题的问题。就是一类 NP 问题，所有的 NP 问题都可以多项式时间归约到它，它是 NP 里面最难的一批。

举例的话，在前面的旅行商问题的基础上面再改一改，旅行商在限制花费时是否可行问题：设一个人需要从香港出发，经过广州，北京，上海等等 n 个城市，最后回到香港。任意两个城市之间都有飞机直达，单双向的票价不等。假设预算 C 元，问是否存在一个行程安排，使得他能遍历所有城市，而且总路费小于 C？

要想知道一条总路费小于 C 的行程是否存在，在最坏的情况下，必须检查所以可能的旅行安排才能找到，即 (n−1)! 种方案，很显然这不是 P 问题。而给出任意一个行程安排，很容易就能验证总路费是否小于 C。所以这是 NP 问题。依旧是哈密顿问题可以归约到这个问题上面，所以这个问题是 NP 完全问题。

结语

我们可以给出一个图，非常形象地表达四类 P 问题的关系。

简单讲讲千禧年难题吧，也就是那个 P=NP or P≠NP 问题。简单来讲，如果一个问题的答案，给你之后你能很快验明真假；那是不是代表，这个答案本身，也一定能被很快找出来？

  • 如果 P=NP ：只要能快速验算，就一定能快速求解。不存在 “验算容易、找解很难” 的问题。
  • 如果 P≠NP ：存在一类问题，验证答案很轻松，但是想凭空找出正确答案，没有快速办法，只能暴力试很多可能性。

前面我们知道 NPC 是 NP 里面最难的一批，而且可以被其他 NP 问题归约，只要随便找到任意一个 NPC 问题的快速求解算法，就能证明 P=NP ，所有 NP 里 “好验证、难找解” 的难题，全部都有快速解法。

这个问题至今悬而未决，但是不同领域的发展下来，大家更加偏向于 P≠NP 是正确的，但是到底是因为这个真的是不等于，还是只是说人类自己没有找到快速的解法呢？这就不得而知了，反正就是没有被数学严谨证明或证伪。
